# Swagger Petstore - OpenAPI 3.0

A sample pet store server based on the OpenAPI 3.0 specification. Used by the apitame examples. The public demo server resets its data regularly.

These tools come from the `petstore` MCP server, generated by apitame from the OpenAPI spec.
The server runs in **read-only mode**: 11 write operations are blocked.

## Tools

| Tool | Use it to | Operations |
| --- | --- | --- |
| `pet` | Everything about your pets | `findPetsByStatus`, `findPetsByTags`, `getPetById` |
| `user` | Operations about users | `loginUser`, `logoutUser`, `getUserByName` |
| `store` | Access to Petstore orders | `getInventory`, `getOrderById` |
| `search_operations` | Find any of the 19 operations by keyword | all |
| `call_operation` | Call an operation that has no dedicated tool | any available |

Grouped tools take `{"operation": "<operation id>", "params": {...}}`. Results are JSON: `{"status": <http status>, "data": <body>}`.

Add `"fields"` with dot paths to keep only what you need, for example `"fields": ["id", "name", "items.owner.login"]`. Arrays are handled for you, so `items.name` keeps `name` in every item. It saves a lot of context on large responses.

## Workflows

### Finds Pets by status, then open one

1. Call `pet` with `{"operation":"findPetsByStatus","params":{"status":"available"}}`.
2. Take the identifier (`petId`) of the item the user means from the result, then call `pet` with `{"operation":"getPetById","params":{"petId":10}}`.
3. Summarize the fields the user asked about instead of pasting the raw JSON.

### Finds Pets by tags with filters

1. Call `pet` with `{"operation":"findPetsByTags","params":{"tags":["example"]}}`.
2. Useful parameters: `tags`. Ask the user for missing values instead of guessing.

## Safety rules

- Write operations are blocked by the server. Do not look for workarounds. If the user needs one, name the operation and tell them it must be enabled in `apitame.config.yaml` (`mode: read-write` and `writes.allow`).
- Responses over 50 KB are cut. Use filters, pagination and `fields` rather than fetching everything.
- Never ask the user for API keys or tokens: the server already holds them, and they are never shown to you.
- A non-2xx `status` is an API error: read `data` for the reason before retrying.
