# apitame v0.3.0

apitame is now ready for teams: one HTTP server, many people, each with their own permissions, signed in through your own identity provider. Writes can be limited argument by argument, DuckDB joins the SQL sources, and approvals work with the newest MCP protocol, even over stateless HTTP.

**This release has breaking changes** (Node 22.14, stricter config). See [Upgrading](#upgrading).

```bash
npx apitame@0.3 init ./openapi.yaml
npx -p apitame@0.3 -p @duckdb/node-api@1.5.6-r.1 apitame init ./data.duckdb   # new: DuckDB
```

## Highlights

- **Argument rules for writes.** `writes.allow` decides which writes may run; `writes.rules` now limits how: `createRefund: { body.amount: { max: 5000 } }`, `updateIssue: { owner: { in: [acme] } }`. Rules are checked before anything is sent or anyone is asked to approve, fail closed when a value is missing, and are shown to the agent up front in tool descriptions and skills. Patterns run on a linear-time matcher, so a crafted value cannot stall the server.
- **OAuth 2.1 for the HTTP transport.** apitame acts as a resource server for your own authorization server (Keycloak, Auth0, Okta, Entra ID and others that issue JWT access tokens): it publishes protected resource metadata, points MCP clients to the sign-in, and checks every token locally.
- **Per-user permissions and rate limits.** With OAuth, `http.oauth.permissions` gives each scope or client its own tools and write allowlist on top of a read-only `default`, always within the server config. Each user can get their own rate limits, and the audit log records who did what.
- **DuckDB (read-only).** `init ./data.duckdb` works like SQLite. The driver is an optional add-on, so the default install does not grow, and every query runs in an isolated process with memory, thread and time limits.
- **Approvals with MCP protocol 2026-07-28.** Clients on the newest protocol approve destructive operations through multi round-trip input, which also works over stateless HTTP. Clients on the 2025 protocols behave exactly as before.

## Upgrading

- **Node.js 22.14 or later** is required. Node 20 reached end of life in April 2026, and the SQLite driver crashes on Node 22 before 22.14.
- **Unknown config keys are errors.** A typo at the top level of `apitame.config.yaml`, under `http` or under `writes` used to be ignored silently; it now stops with a message that names the key and suggests the right one. Run `npx apitame@0.3 doctor` to check your config.
- **`confirmation.method: elicitation` refuses approvals over HTTP without authentication,** because any local process that can reach the port could approve them itself. Use stdio, or set `APITAME_HTTP_TOKEN` or `http.oauth`. The default (`auto`) is unchanged.
- **Client configs** written by `add-to` pin `apitame@0.2`. Run `npx apitame@0.3 add-to <client> --write` again, or edit the version. For Codex, edit `.codex/config.toml` by hand: `add-to` never changes an existing `[mcp_servers.<name>]` entry.
- The default install is about 13 MB larger (better-sqlite3 13 ships prebuilt binaries for every platform).

## Security

Every new feature in this release was reviewed by an independent adversarial review before it was merged, and every finding was fixed with a test that fails without the fix: OAuth (token confusion, redirects, typos that disabled settings), the new approvals (what an approval proves on unauthenticated HTTP), DuckDB (a query that could crash the server, the timeout during planning, proxy credentials) and per-user permissions (entries that combined into more access than either granted). The SQL lexer now also ends PostgreSQL comments at a carriage return, as the server does.

The full list is in the [changelog](https://github.com/albert-canfield/apitame/blob/v0.3.0/CHANGELOG.md).
