# apitame v0.2.0

More sources, more clients, stronger guardrails, a much smaller install, and the fixes from three safety reviews. **Upgrading from 0.1.0 is recommended.**

```bash
npx apitame init mysql://readonly:pass@localhost:3306/shop   # new: MySQL and MariaDB
npx apitame init ./swagger.json                                # new: Swagger 2.0
npx apitame doctor                                             # new: what to fix, if anything
npx apitame serve --watch                                      # new: config changes apply live
npx apitame serve --transport http --sessions                  # new: approvals in the client over HTTP
```

## Highlights

- **MySQL and MariaDB.** Same tools and guarantees as PostgreSQL and SQLite: guarded SELECT-only `query`, named queries, read-only transactions, server-side timeouts and row limits. The lexer follows MySQL's own rules, including refusing `/*! ... */` executable comments, which MySQL runs even though SQL parsers treat them as comments.
- **Swagger 2.0.** Converted to OpenAPI 3 in memory, including form data, file uploads, `collectionFormat` and security definitions.
- **Big APIs.** Stripe's full spec (612 operations) becomes 12 tools in about 4,400 tokens; a one-tool-per-endpoint server would need about 434,000. GitHub's full REST API (1,242 operations) fits in about 9,100.
- **`apitame doctor`.** Checks config, environment variables, `.env` safety, connectivity and credentials, warns when a database role could write, catches allowlist typos, and spots stale skills and missing client configs.
- **Guardrails.** Per-minute limits on calls (120), writes (20) and, optionally, individual tools stop runaway agent loops; an optional JSON Lines audit log records every write attempt and refused query, redacted.
- **Response field selection.** `"fields": ["items.full_name", "items.stargazers_count"]` returns only what the agent needs.
- **File uploads.** Multipart and binary bodies, with files passed inline (never as local paths) and a size cap.
- **Live reload.** `serve --watch` applies config, spec, skills and `.env` changes and tells clients the tool list changed; an invalid config never takes the server down.
- **Approvals over HTTP.** `serve --transport http --sessions` keeps a session per client, so destructive actions are approved by the human in the client (elicitation), as over stdio.
- **More clients.** `add-to gemini` and `add-to claude-desktop` (absolute paths for desktop apps, skills packaged for upload).
- **Install size** down from about 141 MB to 53 MB.

## Security

Three internal safety reviews before this release found and fixed the following. Everything here affects 0.1.0, except the MySQL items, which concern features new in this release.

Secrets
- A secret echoed by an API right where a response is cut to `maxResponseBytes` could be partly shown, because responses were trimmed before redaction. Redaction now runs first (HTTP responses, SQL results, OAuth errors).
- Values from `${VAR}` in `source.baseUrl` (a bot token in the URL path) and each variable inside a composite value (`SSWS ${TOKEN}`) are treated as secrets.
- The redactor catches more shapes (query-string encoding, `Authorization:` pairs, object keys) and no longer backtracks quadratically: one 200 KB argument could block the server for about 20 seconds.

SQL
- `sql.tables.allow` could be bypassed with a CTE named like a real table, and both table lists with functions that run a SQL string (`ts_stat`, `ts_rewrite`, `crosstab`). Planner statistics (`pg_stats`, `sqlite_stat4`) and other sessions' statements (`pg_stat_get_activity`) are denied too.
- MySQL: a dry run, and the row count shown before a human approves, really changed MyISAM and other non-transactional tables. Dry runs now require InnoDB tables without triggers.
- Named query parameters are bound with their validated types, and `writes.destructive` patterns apply to them.
- Database comments and names no longer reach generated skill files as raw markdown, where a comment could add instructions.

Writes and confirmation
- `"dryRun": "true"`, `1` or `null` sent the real request; `dryRun` and `confirm` could be taken over by API parameters of the same name. Both fixed.
- A prompt that fails or is not answered stops the call instead of falling back to a token the agent could send itself. A rate-limited call no longer uses up the human's approval, and `writes.destructive` and `writes.treatAsRead` accept `*` patterns at runtime.

HTTP
- Credentials never come back to a redirect chain that left the API origin, writes are not resent outside the base URL, exploded object query parameters only accept declared keys, and `timeoutMs` covers the whole request (on Node 20 the timeout could stop working entirely).

Also in this release: path parameters `.` and `..` are refused, credentials never follow a redirect to another host, more credential catalogs are denied, and the HTTP transport's checks are covered by tests.

## Upgrading

Configs written for 0.1.0 keep working (one rare exception below). A few things now behave differently:

- Rate limits are on by default: 120 tool calls and 20 writes per minute. Raise them with `limits.maxCallsPerMinute` and `limits.maxWritesPerMinute`, or set `0` to turn a limit off.
- `dryRun` must be `true` or `false`; other values are refused instead of being treated as false.
- If an API has its own parameter called `dryRun` or `confirm`, single-operation tools expose it as `api_dryRun` or `api_confirm`.
- SQL named query parameters cannot be called `dryRun` or `confirm` (a config validation error).
- On MySQL, dry runs need InnoDB tables without triggers; otherwise the preview shows "unknown" rows.
- With `sql.tables.allow`, a CTE named like a real table is treated as that table.

Client configs written by `add-to` pin `apitame@0.1`. To move to 0.2, run `npx apitame@0.2 add-to <client> --write` again, or edit the version. For Codex, edit `.codex/config.toml` by hand: `add-to` never changes an existing `[mcp_servers.<name>]` entry.

The full list is in the [changelog](https://github.com/albert-canfield/apitame/blob/v0.2.0/CHANGELOG.md).
