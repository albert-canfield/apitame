# apitame v0.1.0

The first release. One command turns an OpenAPI spec or a SQL database into a safe MCP server plus agent skills.

```bash
npx apitame init ./openapi.yaml
npx apitame add-to claude-code --write
```

## Highlights

- **Safe by default.** Read-only mode out of the box. Writes need `mode: read-write` and an allowlist entry. Destructive operations need human approval, through MCP elicitation when the client supports it or a one-time token bound to the exact arguments. Every write supports `dryRun`.
- **Curated tools.** Endpoints are grouped by tag into a capped number of task-level tools, with `search_operations` and `call_operation` for the long tail. The GitHub example goes from 38 endpoints to 8 tools and about 65% fewer tokens.
- **SQL sources.** PostgreSQL and SQLite with `list_tables`, `describe_table`, a SELECT-only `query` and named, parameterized queries. Queries pass a database-accurate lexer, a SQL parser and database-level read-only enforcement, with a row limit and timeout.
- **Generated skills.** Deterministic `SKILL.md` files with the real tool names, workflows and safety rules. Installed by `add-to` for Claude Code, Codex, Cursor and VS Code, and served over MCP through the Skills extension.
- **Token visibility.** `apitame inspect` estimates the tool-list cost, compares it with one tool per endpoint and with search-only, and fails CI with `--max-tokens`.
- **Built-in testing.** `apitame test` calls every read tool against a mock built from the spec (or the live API), validates responses, and proves blocked writes never leave the process. For SQL it checks every table and replays known injection payloads.

## Details

- OpenAPI 3.0 and 3.1, JSON or YAML, files or URLs, external `$ref`s, spec discovery from a base URL.
- Auth: bearer, API key (header, query, cookie), basic, OAuth2 client credentials with caching and refresh on 401. Secrets only from environment variables or `.env`, redacted from every output.
- Transports: stdio, and stateless streamable HTTP with loopback binding, Host and Origin checks and a required bearer token beyond loopback.
- Built on the MCP TypeScript SDK v2. Node.js 20.12 or later.

## Known limitations

- `multipart/form-data` and binary request bodies are not supported yet; those operations are listed as unsupported.
- Swagger 2.0 must be converted to OpenAPI 3 first.
- Token counts are estimates; tokenizers differ between models.
- The SQL parser does not understand every PostgreSQL extension; such free-form queries are refused and can be added as named queries.
